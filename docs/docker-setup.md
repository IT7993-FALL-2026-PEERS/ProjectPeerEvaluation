# Docker setup (M2)

Docker is a **local-dev and CI convenience** for PEERS. It does not replace the Render
deployment (see README "Deployment") or the plain `npm run dev` path; use whichever you like.

The stack is three services started in order, each waiting for the previous one to be **healthy**:
`mongo` → `backend` → `frontend`.

| Service | Image | Port on your machine | Healthy when |
|---|---|---|---|
| `mongo` | `mongo:7` | 27017 (loopback only) | `mongosh` ping succeeds |
| `backend` | built from `src/backend/Dockerfile` | 5000 | `GET /api/health` returns 200 (Mongo connected) |
| `frontend` | built from `Dockerfile.frontend` (nginx) | 3000 | `GET /` returns 200 |

## Prerequisites

- Docker Engine/Desktop with **Compose v2.24 or newer** (`docker compose version`).
- Node 24 only if you use the `npm run` shortcuts (`npm run docker:up` creates `.env` for you).
  Without Node, copy `.env.example` to `.env` yourself and set `JWT_SECRET`.
- Free ports 3000, 5000, 27017 (or change them in `.env`).
- Windows: use Docker Desktop with the WSL 2 backend. Keep the repo on LF line endings
  (`.gitattributes` enforces this for scripts and Dockerfiles).

## Quick start

```bash
npm run docker:up        # creates .env if missing, builds, starts, waits until healthy
bash scripts/verify-env.sh
npm run docker:down      # stop (data kept)
```

Equivalent without npm: `cp .env.example .env` (edit `JWT_SECRET`), then
`docker compose up --build -d --wait`.

## Environment variables

Compose reads the **root** `.env` (copied from `.env.example`). The non-Docker path uses
`src/backend/.env` instead; they are separate files on purpose.

| Name | Purpose | Required? | Example |
|---|---|---|---|
| `JWT_SECRET` | Signs login tokens; the container runs with `NODE_ENV=production`, so ≥ 32 chars | **Yes** (Compose refuses to start without it) | 96 random hex chars, generated by setup |
| `DOCKER_MONGODB_URI` | Mongo URI inside the compose network | No (default `mongodb://mongo:27017/peer-eval`) | `mongodb://mongo:27017/peer-eval` |
| `FRONTEND_PORT` / `BACKEND_PORT` / `MONGO_PORT` | Host ports | No (3000 / 5000 / 27017) | `3001` |
| `FRONTEND_API_URL` | URL the **browser** uses for the API; **baked into the frontend image at build time** | No | `http://localhost:5000/api` |
| `FRONTEND_URL` | Base of links in invitation/reset emails | No | `http://localhost:3000` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | Outgoing email | Only to send email | Mailtrap sandbox values |
| `EMAIL_SEND_INTERVAL_MS`, `EVALUATION_TOKEN_TTL_DAYS` | Email pacing / link lifetime | No | `0`, `14` |

Notes:
- `REACT_APP_*` values are compiled into the JavaScript bundle. Changing `FRONTEND_API_URL`
  needs `docker compose up --build`; it is public, so never put a secret in it.
- The backend accepts browser calls only from the origin of `FRONTEND_URL` (`src/backend/config/corsConfig.js`).
  If you change `FRONTEND_PORT`, set `FRONTEND_URL` to match (e.g. `http://localhost:8080`), or the browser
  will block API calls.
- Inside containers `localhost` means the container itself. Services reach each other by name (`mongo`, `backend`).

## Everyday commands

```bash
docker compose up --build -d --wait   # start / rebuild; --wait fails if a service is unhealthy
docker compose ps                     # STATUS shows (healthy), (unhealthy) or (health: starting)
docker compose logs -f backend        # follow one service (omit name for all)
docker compose restart backend
docker compose down                   # stop, keep the database volume
docker compose down -v                # stop AND delete the database (fresh start)
docker compose build --no-cache       # fix stale images
```

Reading health: `docker inspect --format '{{json .State.Health}}' peers-backend-1` shows the last
check outputs.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `port is already allocated` / `address already in use` | Another app uses 3000/5000/27017 (often a local `mongod` or `npm run dev`). Stop it or change the port in `.env`. |
| `JWT_SECRET is not set` when running compose | No `.env`. Run `npm run setup` (or `node scripts/setup.js --env-only`) or copy `.env.example`. |
| Backend restarts: `Invalid configuration: JWT_SECRET is too short` | Under `NODE_ENV=production` the secret needs ≥ 32 chars. Re-generate it (see `.env.example`). |
| Backend `unhealthy`, `/api/health` says `DEGRADED` | Backend is up but not connected to Mongo. Check `docker compose ps mongo` and `DOCKER_MONGODB_URI` (must use `mongo`, not `localhost`). |
| Frontend still calls the old API URL | Stale image: `docker compose up --build`. The URL is fixed at build time. |
| Browser CORS error | `FRONTEND_URL` doesn't match the address the frontend is opened at (see Notes). |
| Code changes not showing | Images are built from the files, not mounted. Rebuild after code changes. |
| `env_file ... required` error | Compose older than v2.24. Upgrade Docker. |
| Windows: `exec ... no such file` or `\r` errors | CRLF line endings. Re-checkout after `.gitattributes` is present, or `git config core.autocrlf input`. |

## Known limitations

- No hot reload: this stack runs production builds. For day-to-day coding use `npm run dev`.
- Uploaded files (`src/backend/uploads/`, used by CSV roster upload) live inside the backend container and are lost when it is recreated.
- Mongo has no authentication and is bound to loopback only; this is a dev stack, not a deployment.
